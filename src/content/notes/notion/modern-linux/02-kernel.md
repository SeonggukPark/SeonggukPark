# (1) 리눅스 아키텍처
![모던 리눅스 2. 리눅스 커널 이미지](/SeonggukPark/images/notion/notes/modern-linux/02-kernel-1.png)
→ **HW 계층**
- CPU \~ 주변 디바이스까지 모두 일컫는다
→ **커널 계층**
- 커널과 사용자 사이의 init 시스템, 시스템 서비스들은 엄밀히 따지면 커널의 일부가 아님
→ **사용자 영역 계층**
- 셸 같은 운영체제 구성요소 , ps나 ssh 같은 유틸리티 같은 대부분 앱이 실행 되는 곳

- 사용자 모드와 커널 모드가 존재 (접근 권한, 추상화 제한 차이)
- 사용자 모드: 상대적으로 느리지만 더 안전하고 편리한 추상화
- 커널 모드: 추상화 제한 → 빠르게 실행
- 모든 앱이 사용자 영역에서 실행
→ 커널 개발자가 아닌 이상 커널 모드 무시 가능
→ 하지만 커널과 상호작용 하는 방법을 아는건 중요

# (2) CPU 아키텍처
- 리눅스난 다양한 CPU 아키텍쳐에서 실행되서 인기있음 
→ 코드 분리 덕분에 하드웨어 이식성 ↑
### BIOS & UEFI
- **컴퓨터 전원이 켜질 때 하드웨어를 초기화하고 운영체제를 부팅하는 펌웨어 인터페이**
- BIOS(Basic I/O System)
- 전통적인 부팅 방식 
- 16비트 환경에서 동작
- 전원 ON → BIOS 실행 → POST 수행 → MBR 읽기 → OS 부팅
- UEFI(Unified Extensible Firmware Interface)
- BIOS를 대체하기 위해 등장한 최신 부팅 인터페이스
- 32/64비트 환경에서 동작
- 전원 ON → UEFI 실행 → 하드웨어 초기화 → EFI 파티션에서 부트로더 실행 → OS 부팅

### 실행 중인 CPU 파악 방법
**\[1\] dmidecode 이용**
-  BIOS와 상호 작용하는 전용 도구

## x86 아키텍처
- 인텔에서 개발했으며 나중에 AMD에도 라이선스된 명령어 세트 제품군
- x64: 인텔 64비트 프로세서
- x86: 인텔 32비트 프로세서
- amd64: AMD 64비트 프로세서
- x86은 서버에서도 널리 사용
- 멜트다운 (인텔 CPU, ARM 등에서 발견된 보안 취약점, 사용자 영역에서 OS의 시스템 메로리 접근 가능) 으로 최근 관심 많이 받음

## ARM 아키텍처
- RISC 아키텍처 제품군
- x86보다 빠르고 저렴하며 발열량이 적어 데이터 센터에서 적합
- 스펙터 같은 취약점에 영향 받지 않음

## RISC-V 아키텍처
- US버클리에서 개발한 개방형 RISC 표준
- 비교적 새롭고 널리 사용되지 않는 CPU 제품군으로, 연구가 더 필요

# (3) 커널 구성요소
- 커널은 하드웨어와 실행하려는 앱 사이 존재
- 커널의 주요 기능은 다음과 같다
- 프로세스 관리: 실행 파일을 기반으로 프로세스 시작
- 메모리 관리: 프로세스에 메모리를 할당하거나 파일을 메모리에 매핑
- 네트워킹: 네트워크 인터페이스 관리나 네트워크 스택 제공
- 파일 시스템: 파일 관리 제공, 파일 생성 및 삭제 지원
- 캐릭터 디바이스와 디바이스 드라이버 관리

## 프로세스 관리
- 프로세스 : 실행 가능한 프로그램(or 바이너리) 기반
- 스레드 : 프로세스 컨텍스트 상에서의 실행 유닛
### 세션
- 하나 이상의 프로세스 그룹 포함
- 선택적으로 tty가 연결된 상위 수준의 사용자 대면 유닛
- 커널은 세션ID(SID)를 통해 세션 식별
### 프로세스 그룹
- 하나 이상의 프로세스 포함
- 한 세션에는 foreground 프로세스 그룹이 둘 이상일 수 없음
- 커널은 프로세스그룹ID(PGID)를 통해 프로세스 그룹을 식별
### 프로세스
- 여러 리소스(주로 공간, 스레드, 소켓 등)를 그룹으로 추상화 한것
- 커널은 `/proc/self` 를 통해 현재 프로세스를 사용자에게 노출
- 커널은 프로세스ID(PID)를 통해 프로세스 식별
### 스레드
- 커널에 의해 프로세스로 구현된 유닛
- 커널은 스레드ID(TID)와 스레드그룹ID(TGID)를 통해 스레드 식별
- 공유된 TGID → 멀티스레드 프로세스 의미
### 태스크
- 앞선 모든 유닛은 태스크에서 파생 또는 고정됨
- 태스크는 커널 외부에 그대로 노출되는 일이 없음
![모던 리눅스 2. 리눅스 커널 이미지](/SeonggukPark/images/notion/notes/modern-linux/02-kernel-2.png)
→ 실제 프로세스는 인터럽트 가능 여부가 다른 절전모드 및 좀비 상태 등 더욱 복잡함

## 메모리 관리
### 가상 메모리
- 시스템이 물리적으로 갖고 있는 것 보다 더 많은 메모리르 갖고 있는 것처럼 보이게 하는 기법
![모던 리눅스 2. 리눅스 커널 이미지](/SeonggukPark/images/notion/notes/modern-linux/02-kernel-3.png)
→ 물리 메모리, 가상 메모리 모두 **페이지**라는 고정 길이의 청크로 나눔
→ 페이지 테이블은 프로세스의 가상 페이지를 RAM의 물리적 페이지에 매핑
→ 여러 가상 페이지가 동일한 물리적 페이지를 가리킬 수 있음
→ 기존 공간을 최적으로 사용하면서 프로세스에 그들의 페이지가 실제 RAM에 존재한다는 환상 유발 가능

- 최신 CPU 아키텍처는 [TLB](https://en.wikipedia.org/wiki/Translation_lookaside_buffer)라는 매우 작은 캐시를 활용해 주소 변환 속도 개선 (가상 주소 → 물리 주소)
- 전통적으로 리눅스 기본 페이지 크기는 4KB 였으나, 커널 버전 v2.6.3부터는 대형 페이지 지원
- `/proc/meminfo` 인터페이스 통해 메모리 관련 정보 파악 가능
![모던 리눅스 2. 리눅스 커널 이미지](/SeonggukPark/images/notion/notes/modern-linux/02-kernel-4.png)
→ `grep MemTotal /proc/meminfo` : RAM에 대한 세부 정보 나열, 여기서는 8GB
→ `grep VmallocTotal /proc/meminfo` : 가상 메모리에 대한 세부 정보 나열, 여기서는 34TB ↑
→ `grep Huge /proc/meminfo` : 대형 페이지 정보 나열, 여기서 페이지는 2MB

## 네트워킹
- 소켓 : 추상화 커뮤니케이션을 위해 필요
- TCP & UDP : 연결형 & 비연결형 통신용
- IP : 기기의 주소 지정 위해 필요
→ 이 3개는 커널이 처리하는 모든 것이며, HTTP, SSH 같은 어플리케이션 계층 프로토콜은 주로 사용자 영역에서 구현

![모던 리눅스 2. 리눅스 커널 이미지](/SeonggukPark/images/notion/notes/modern-linux/02-kernel-5.png)
→ 네트워크 인터페이스 개요

## 파일시스템
- 리눅스는 파일시스템 사용해 HDD, SDD 같은 저장 디바이스의 파일과 디렉터리 구성
- ext4, NTFS 같은 다양한 유형의 파일 시스템 존재
- 동일 파일시스템에서 여러  인스턴스 사용 가능
- VFS(가상 파일시스템)은 여러 파일시스템 유형과 인스턴스 지원 위해 도입, 공통 API 추상화 제공

## 디바이스 드라이버
- 드라이버 : 커널에서 실행되는 코드, 실제 하드웨어 디바이스나 의사 디바이스를 관리하는 역할
→ 의사 디바이스: 실제 하드웨어는 존재하지 않지만, 장치처럼 동작하도록 제공하는 가상 파일
→ 커널에 정적으로 빌드, 필요할 때 동적으로 로드될 수 있도록 커널 모듈로 빌드 가능

## 시스템 콜
- 커널이 노출하는 서비스 인터페이스와 해당 사용자 영역의 엔티티 호출은 **시스템 콜**이라 부름
- 리눅스에는 수백 개의 시스템 콜 존재 (CPU 제품군 마다 다르지만, 약 300개 이상)
### 시스템 콜 실행 단계
![모던 리눅스 2. 리눅스 커널 이미지](/SeonggukPark/images/notion/notes/modern-linux/02-kernel-6.png)
\[1\] syscall.h와 아키텍처 종속 파일에 정의되어 메모리에 있는 함수 포인터 배열(sys_call_table)을 통해 시스템 콜과 핸들러 추적
\[2\] system_call() 함수를 사용하면 hw 컨텍스트를 스택에 저장한 다음 검사 수행 (추적 여부 등), 그 다음 sys_call_table의 각 시스템 콜 번호의 인덱스가 가리키는 함수로 점프
\[3\] sysexit으로 시스템 콜이 완료되면 래퍼 라이브러리는 hw 컨텍스트 복원, 프로그램은 사용자 영역에서 다시 실행
→ 커널 모드 - 사용자 모드간의 전환은 시간이 많이 소요
