# (1) 프로세스 간 통신
- IPC는 프로세스가 통신하고, 활동을 동기화하고, 데이터를 공유할 수 있게 해줌
- e.g.) 도커 데몬 → 컨테이너 관리에 맞춰 구성 가능한 소켓 사용

## 시그널
- 커널이 특정 이벤트를 사용자 공간 프로세스에 알리기 위한 방법으로 개발
- 프로세스에 전송되는 비동기 알람
- 대부분 프로세스 중지, 종료 같은 기본 동작이 함께 제공
- 대부분 커스텀 핸드러를 정의 → 정리 작업, 특정 시그널 무시 등 상황에서 유용
![모던 리눅스 9. 심화 주제 이미지](/SeonggukPark/images/notion/notes/modern-linux/09-advanced-topics-1.png)

- 프로세스에 시그널을 보내는 방법 중 하나가 kill 명령
→ 직접 프로세스를 제거하는게 아니라, 프로세스에 종료 시그널을 보내는 명령
![모던 리눅스 9. 심화 주제 이미지](/SeonggukPark/images/notion/notes/modern-linux/09-advanced-topics-2.png)
→ 시그널을 이용해 백그라운드 프로세스를 종료

- trap을 이용해 시그널 처리 가능
→ 셸 환경에서 커스텀 핸들러 정의 가능
![모던 리눅스 9. 심화 주제 이미지](/SeonggukPark/images/notion/notes/modern-linux/09-advanced-topics-3.png)
→ 기존 SIGINT의 기본 동작인 프로세스 종료를 trap으로 대체

## 이름 있는 파이프
- 파일 시스템에 이름을 가진 프로세스 간 통신(IPC) 통로
- pipefs 의사 파일시스템을 사용하는 파이프의 래퍼
### 예제: examplepipe
![모던 리눅스 9. 심화 주제 이미지](/SeonggukPark/images/notion/notes/modern-linux/09-advanced-topics-4.png)
![모던 리눅스 9. 심화 주제 이미지](/SeonggukPark/images/notion/notes/modern-linux/09-advanced-topics-5.png)

- 이처럼 named pipe는 사용하기 쉽지만, 한 방향, 한 컨슈머만 지원하기 때문에 제한적
## 유닉스 도메인 소켓
- 양방향 다자간 통신 엔드포인트
- 스트림 지향, 데이터그램 지향, 시퀀스 패킷 등 세 가지 종류로 제공
- 굳이 IP 주소와 포트를 사용하지 않고 간단한 파일 경로를 써도 충분
- 일반적으로는 프로그래밍 방식으로 도메인 소켓 사용

# (2) 가상 머신
## 커널 기반 가상 머신
- 리눅스 커널을 하이퍼바이저처럼 동작하게 만드는 가상화 기술
## 파이어크래커
- KVM 인스턴스를 관리할 수 있는 가상 머신 모니터
- RUST로 작성, 주로 AWS 람다와 AWS 파게이트 같은 서버리스 제품을 위해 아마존에서 개발

# (3) 모던 리눅스 배포판
- 전통적으로 레드햇(RHEL, CentOS/Rocky), 데비안(Ubuntu, Mint) 등 많이 사용
- 모던 리눅스 배포판이란, 컨테이너 중심의 배포판을 의미
→ 불변성과 자동 업그레이드가 가장 중요
## 레드햇 엔터프라이즈 리눅스 코어OS
- 패키지 관리자가 없음 → 모든 앱은 기본적으로 컨테이너로 실행
## 플랫카 컨테이너 리눅스
- 쿠버네티스와 IoT/엣지 컴퓨팅 같은 컨테이너 오케스트레이터로 사용할 수 있는 컨테이너 네이티브 경량 OS
## 보틀로켓
- AWS에서 개발한 리눅스 기반 컨테이너 호스팅용 OS
- 패키지 관리자 대신 OCI 이미지 기반 모델 사용
## 랜처OS
- 전부 도커에서 관리하는 컨테이너로 이뤄진 리눅스 배포판
