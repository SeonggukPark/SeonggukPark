## 6-1. 파일 설계의 개요

[Notion 원본](https://app.notion.com/p/3416b9674ad88092aed6d4ee31fabbd7)

### (1) 자료의 기본 구성
#### 1) 비트(Bit)
- 자료를 표현하는 **가장 작은 단위**
#### 2) 니블(Nibble)
- 4비트를 묶은 단위
#### 3) 바이트(Byte)
- 8비트를 묶은 단위
#### 4) 워드(Word)
- CPU가 **한 번에 처리하기 가장 효율적인 데이터 단위**
- 고정된 절대값이 아니라 **시스템/CPU 기준 단위**
**예**:
- 16비트 CPU → 워드 크기 16비트
- 32비트 CPU → 워드 크기 32비트
![6-1. 파일 설계의 개요 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-01-1.png)
#### 5) 필드(Field)
- 하나의 항목에 해당하는 자료의 모임
- e.g.) 학생부에서 번호, 이름, 학번 각각이 필드
![6-1. 파일 설계의 개요 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-01-2.png)
#### 6) 레코드(Record)
- 여러 개의 **필드가 모여** 한 사람, 한 물건, 한 사건 등을 나타내는 단위<br>
#### 7) 파일(File)
- 여러 개의 **레코드가 모여 구성된 것**
#### 8) 데이터베이스(Database)
- 여러 파일을 **체계적으로 통합하여 저장한 데이터 집합**
#### 9) 데이터 웨어하우스(Data warehouse)
- 여러 시스템에 흩어진 데이터를 모아 **분석과 의사결정**에 쓰기 좋게 정리한 대규모 저장소
#### 10) 빅데이터(Big Data)
- **양이 매우 많고**, **형태가 다양하며**, **생성 속도도 빠른 데이터**

### (2) 파일의 구성
#### 1) 논리적 레코드와 물리적 레코드
- 논리적 레코드 : 사용자 or 프로그램이 **의미 있는 하나의 단위로 인식하는 레코드 (학생 1명 정보)**
- 물리적 레코드 : 저장장치(디스크 등)에 **실제로 저장되는 단위**
![6-1. 파일 설계의 개요 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-01-3.png)
#### 2) 레코드의 형식
![6-1. 파일 설계의 개요 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-01-4.png)
##### \[1\] 비블록화 고정길이 레코드
- 하나의 논리레코드가 하나의 물리레코드 구성
- 처리 속도 낮은 대신 프로그램 작성 용이
![6-1. 파일 설계의 개요 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-01-5.png)
##### \[2\] 블록화 고정길이 레코드
- 동일한 길이의 레코드를 하나의 블록으로 묶어 저장
- 처리 속도 향상, 프로그램 작성 용이
![6-1. 파일 설계의 개요 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-01-6.png)
##### \[3\] 비블록화 가변길이 레코드
- 길이가 다른 레코드를 하나씩 저장
![6-1. 파일 설계의 개요 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-01-7.png)
##### \[4\] 블록화 가변길이 레코드
- 길이가 다른 여러 레코드들을 하나의 블록으로 구성
![6-1. 파일 설계의 개요 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-01-8.png)

### (3) 파일의 종류
#### 1) 매체에 의한 분류
- 자기디스크, CD-ROM 등

#### 2) 내용에 의한 분류
![6-1. 파일 설계의 개요 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-01-9.png)
→ **마스터 파일** : 시스템 운영 **기준이 되는 핵심 데이터 파일 (기본적으로 계속 사용되는 기준 데이터)**
→ **트랜잭션 파일** : 마스터 파일을 수정하는 입력 자료
→ **트레일러 파일** : 파일의 무결성 확인용

#### 3) 파일 편성에 의한 분류
- 순차 파일 : 앞에서부터 차례대로 읽는 방식
- 색인 순차 파일 : 순차 저장 + 색인 검색 기능 추가
- 랜덤 파일 : 해시(Hash) 함수 또는 주소 계산 방식 사용
- 리스트 파일 : 레코드 간 연결 관계를 이용해 접근

## 6-2. 파일 편성의 설계

[Notion 원본](https://app.notion.com/p/3416b9674ad881a8b634e0cab7940842)

### (1) 순차 파일
- SAM(Sequential Access Method) 파일이라고도 한다
#### 1) 순차 파일의 장점
- 파일 구조가 단순함
- 저장 공간 이용 효율이 높음
- 대량의 일괄 처리(batch processing)에 유리
#### 2) 순차 파일의 단점
- 특정 레코드 검색 시간이 오래 걸림
- 삽입·삭제 시 파일 재구성이 필요
- 임의 접근(Random access)이 어려움
- 실시간 처리에 부적합
#### 3) 대표적인 기록매체
- 자기테이프 (Magnetic Tape)
#### 4) 응용파일
- 배치 처리 중심 업무에 적합 (급여, 성적 처리 등)

### (2) 색인 순차 파일
- ISAM(Index Sequential Access Method) 파일이라고도 한다
#### 1) 구성
##### \[1\] 인덱스 구역 (Index)
- 레코드 위치 정보 저장
- 빠른 검색 지원
##### \[2\] 기본 데이터 구역 (Prime)
- 실제 데이터 저장 영역
- 키 값 순서대로 저장
##### \[3\] 오버플로우 구역 (Overflow)
- 삽입 시 기존 영역 부족할 때 사용
#### 2) 색인 순차 파일의 장점
- 순차 처리 가능
- 직접 접근 가능
- 검색 속도 빠름
- 삽입 처리 유연함
- 대화형 처리 가능
#### 3) 색인 순차 파일의 단점
- 색인 영역 추가 필요
- 저장 공간 추가 사용
- 구조 복잡
- 색인 관리 필요
- 오버플로 영역 증가 시 성능 저하
#### 4) 사용되는 기록매체
- 자기디스크 (Magnetic Disk)
#### 5) 응용파일
- 검색과 갱신이 모두 필요한 업무에 적합 (인사 관리, 고객 관리 등)

### (3) 랜덤 파일
#### 1) 주소 계산
- 저장 위치 주소를 직접 계산 (해시 함수(Hash function) 사용)
#### 2) 직접 사상기법(direct mapping)
- 키 값을 이용하여 저장 주소를 직접 계산하는 방법
![6-2. 파일 편성의 설계 이미지](/SeonggukPark/images/notion/notes/software-engineering/06-02-1.png)
#### 3) 디렉토리 조사기법(directory look up)
- 디렉토리(색인표)를 이용하여 저장 위치를 찾는 방법

### (4) 리스트 파일
#### 1) 장점
- 레코드 삽입 용이
- 레코드 삭제 용이
- 저장 구조 유연함
- 기억 공간 활용 효율적
#### 2) 단점
- 검색 속도 느림
- 포인터 관리 필요
- 구조 복잡
- 순차 처리 외 접근 비효율적

#### 2) 주요 매체
##### 1) 자기 테이프
- 자기테이프 길이 = ( ( 블록 길이 / 기록 밀도 ) + IBG 길이 ) \* (전체 레코드 수 / 블록 내 레코드 수)
→ IBG : 블록과 블록 사이의 간격
##### 2) 자기 디스크
- 실린더 수 = 전체 레코드 수 / (블록 내 레코드 수 \* 실린더 당 블록의 수)
