## 3-1. 코드 설계의 개요

<!-- Notion source: https://app.notion.com/p/33f6b9674ad881d7af3fcb2e10f83c03 -->

### (1) 코드의 정의
- 코드는 데이터 사용 목적에 따라 식별, 분류, 배열하기 위해 사용되는 숫자, 문자 혹은 기호
- 식별: 다른 것과 구별
- 분류: 목적물을 집단으로 구분
- 배열: 순번을 정함

## 3-2. 코드의 종류

<!-- Notion source: https://app.notion.com/p/33f6b9674ad8811cb8a2d479b6db96c7 -->

### (1) 순차 코드 (Sequence Code)
- 일정한 순서에 따라 **연속적으로 번호를 부여하는 방식**
- 의미 없이 단순히 순서만 표현
- 다른 코드와 조합하여 보조 항목으로 사용
**예시**
- 사번: 001, 002, 003 …
- 주문번호: 1001, 1002, 1003 …
**특징**
- 장점: 단순하고 확장 용이
- 단점: 코드 자체에 정보 의미 없음

### (2) 구분 순차 코드 (Block Sequence Code)
- 일정한 **구간(블록)** 을 정하여 각 범위별로 의미를 부여하는 방식
**예시**
- 1000 \~ 1999 : 인사부
- 2000 \~ 2999 : 총무부
- 3000 \~ 3999 : 개발부
**특징**
- 장점: 분류 가능
- 단점: 블록 부족 시 확장 어려움

### (3) 십자 분류 코드 (Decimal Code)
- **10진수 체계**를 이용하여 단계적으로 분류하는 방식
- 계층적 구조 표현 가능
- 자릿수가 지정되지 않으면 기계처리에 부적합
**예시**
- 100 : 컴퓨터
- 110 : 하드웨어
- 111 : CPU
**특징**
- 장점: 계층 구조 표현에 적합
- 단점: 코드 길이가 길어질 수 있음

### (4) 그룹 분류 코드 (Group Classification Code)
- 코드의 각 자리(그룹)가 **서로 다른 의미를 가지는 방식**
**예시**
- 12-03-05
- 12 : 지역
- 03 : 부서
- 05 : 사원번호
**특징**
- 장점: 코드 해석 용이
- 단점: 설계 및 분류가 복잡함, 자릿수가 많음

### (5) 표의 숫자식 코드 (Significant Digit Code)
- 코드의 각 자리 숫자가 **특정 의미를 직접 나타내는 방식**
- 그룹 분류 코드와 유사하지만 **각 자리 자체가 의미를 가짐**
**예시**
- 합판의 두께, 가로, 세로 규격
- 05(합판) 18(두께) 027(가로) 700(세로) → 0518027700
**특징**
- 장점: 코드 자체로 정보 파악 가능
- 단점: 설계 변경 어려움

### (6) 기타 코드
#### 1) 연상 코드 (Mnemonic code)
- 코드의 의미를 **쉽게 연상할 수 있도록 만든 코드**
- 사람이 기억하기 쉽도록 설계됨
**예시**
- KOR : 한국
- BUS : 부산
- HR : 인사부 (Human Resources)
**특징**
- 장점: 기억과 사용이 편리
- 단점: 코드 중복 가능성 존재

#### 2) 약자식 코드 (Letter Type Code)
- 대상의 명칭을 **약자 또는 머리글자 형태로 표현한 코드**
**예시**
- KG: Kilo-Gram
- TEL : Telephone
- COM : Computer
**특징**
- 장점: 의미 전달이 직관적
- 단점: 코드 길이 제한 존재

#### 3) 특정 자릿수 이용코드 (Final Digit Code)
- 코드의 **특정 위치의 숫자(주로 마지막 자리)** 를 이용하여 분류하는 방식
**예시**
- 주민번호 마지막 자리 숫자가 1이면 남자, 2면 여자
**특징**
- 장점: 자동 처리 및 분류에 유리
- 단점: 코드 자체 의미 표현은 제한적

#### 4) 문자식 코드 (Alphabetic Code)
- 숫자가 아닌 **알파벳 문자만으로 구성된 코드**
**예시**
- A : 최우수
- B : 우수
- C : 보통
또는
- AA : 최고 등급
- BB : 중간 등급
**특징**
- 장점: 표현 범위 넓음
- 단점: 정렬 및 처리 시 불편 가능

#### 5) 암호식 코드
- 코드 내용을 **외부에서 쉽게 이해할 수 없도록 만든 코드**
- 보안 목적 사용
**예시**
- 사용자 인증번호
- 암호화된 고객번호
- 보안 접근 코드
**특징**
- 장점: 보안성 우수
- 단점: 해석 어려움
-
#### 6) 합성 코드
- 여러 코드 방식을 **조합하여 만든 코드**
**예시**
- 지역코드 + 부서코드 + 일련번호
- 제품코드 + 생산년도 + 순번
예:
- SE-DEV-001
- SE : 지역
- DEV : 부서
- 001 : 순번
**특징**
- 장점: 다양한 정보 표현 가능
- 단점: 설계 복잡성 증가

## 3-3. 오류 형태와 검출

<!-- Notion source: https://app.notion.com/p/33f6b9674ad881bdb6cdf95d304e7000 -->

### (1) 입력 과정에서의 오류
#### 1) Transcription Error (변위 오류)
- 원래 코드를 잘못 베껴 쓰거나 잘못 입력하는 오류
- 즉, **한 글자나 숫자를 다른 값으로 잘못 적는 오류**
예시
- 원래 코드: 12345
- 잘못 입력: 12845
→ 3이 8로 바뀐 경우
#### 2) Transposition Error (전위 오류)
- 코드의 **자리 순서가 뒤바뀌는 오류**
예시
- 원래 코드: 12345
- 잘못 입력: 13245
→ 2와 3의 위치가 바뀜
#### 3) Double Transposition Error (중복전위 오류)
- 자리 바뀜이 **두 번 이상 발생하는 오류**
예시
- 원래 코드: 123456
- 잘못 입력: 214365
→ 여러 자리의 순서가 복합적으로 뒤바뀜
#### 4) Random Error (랜덤 오류)
- 일정한 규칙 없이 **임의로 발생하는 오류**
- 변위 오류나 전위 오류처럼 일정한 형태로 설명하기 어려운 오류
예시
- 원래 코드: 12345
- 잘못 입력: 18354
→ 숫자가 바뀌고 순서도 일부 달라지는 등 불규칙하게 발생

### (2) 오류 방지를 위한 코드설계와 관리
#### 1) 단순한 코드 체계
#### 2) 코드표 정리
#### 3) 교육 훈련
#### 4) 체계적인 조직
#### 5) 원시전표의 적합성
- 처음 자료를 기록하는 원시전표가 **작성하기 쉽고, 항목이 명확해야** 입력 오류가 줄어듦<br><br>
### (3) 코드 오류방지를 위한 보조기기 사용
#### 1) 고정(중복) 부분 인쇄
#### 2) 고무인 사용
#### 3) 바코드 사용
#### 4) 자동화 코드 부여

### (4) 코드 오류 검출 방법
#### 1) 눈으로 조사
#### 2) 체크 숫자 사용
- 코드 끝에 검사용 숫자(체크 디지트)를 붙여 오류를 검출하는 방법
- 전산 시스템에서 많이 사용

→ modulus 10을 이용한 check digit 생성과정

#### 3) 프로그램에 의한 검사
##### 1) 공백 검사 (Blank Check)
##### 2) 형식 검사 (Mode Check)
##### 3) 유효범위 검사 (Range Check)
##### 4) 일련번호 검사 (Sequence Check)
##### 5) 대조 검사 (Match Check)
##### 6) 한계 검사 (Limit Check)
##### 7) 반향 검사 (Echo Check)
- 입력된 데이터를 **다시 화면에 표시하여 입력자가 직접 확인하도록 하는 검사**
- e.g.) 중요한 정보 입력 후 “입력값 확인” 단계 제공

## 3-4. 코드 설계 순서

<!-- Notion source: https://app.notion.com/p/33f6b9674ad881f68a4dea28265d559a -->

![3-4. 코드 설계 순서 이미지](/SeonggukPark/images/notion/notes/software-engineering/03-04-1.png)
### (1) 코드화 대상 항목 선정과 확인
#### 1) 대상선정
- **관리·분류·검색·처리가 필요한 항목**을 선정
#### 2) 코드의 목적 확정
- 어떤 기능을 중심으로 구성할 것인가를 명확하게 규정
#### 3) 대상확인

### (2) 사용범위와 기간 설정
#### 1) 사용범위
- 컴퓨터 처리로 제한할 것인지, 기업 전체내 사용하는지 등등
#### 2) 사용기간
- 영구적 사용(학번, 주민번호, 군번)
- 일시적 사용(수시변경 가능)

### (3) 코드화 대상 항목의 특성 분석
- 특성을 무시한 코드는 코드로서의 역할 상실 가능
- 다시 변경해야 하는 어려움도 발생

### (4) 코드화 방식 결정
#### 1) 코드 체계의 결정
- 단일 종류의 코드방식 선택하거나 여러 종류 혼합해서 사용도 가능
#### 2) 체크디지트(Check Digit) 사용 결정
- 입력 오류 검출이 중요한 경우 반드시 고려
#### 3) 코드의 자리수
- 초기 코드 설계 시 충분한 자릿수 확보할 것
#### 4) 코드 부여
- 실제 부여하기 위한 원칙 설정

### (5) 코드의 문서화
#### 1) 코드 설정 기준서
- 코드 체계에 대한 설정 기준으로 코드 명, 코드 자릿 수, 코드 구성, 코드 종류를 기술
#### 2) 코드표 작성 방법
- 실무자에게 전달해야 하므로 자세한 설명과 사용법 기술
- 새로운 코드의 추가, 삭제, 정정 등 유지보스가 쉽도록 작성
![3-4. 코드 설계 순서 이미지](/SeonggukPark/images/notion/notes/software-engineering/03-04-2.png)
#### 3) 코드 대장
- 코드 관리 부서에 보관하도록 작성되는 코드 설정기준서, 관리기준 코드표를 의미
