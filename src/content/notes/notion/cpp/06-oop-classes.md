## (1) 객체지향 이전의 프로그래밍 패러다임
- 프로그래밍 패러다임: “프로그램을 어떤 절차와 구조로 만들 것인가”에 대한 스타일, 접근 방식
### 비구조적 프로그래밍
- 코드를 구조화 하지 않고 작성
- 어셈블리어, 포트란

### 절차적 프로그래밍
- 소스 코드를 여러 부분으로 나눠서 활용하는 패러다임
- 프로시저를 이용해 구조화
- 프로시저(procedure): 일련의 코드 묶음, 보통 함수
- C, 코볼, 포트란
- 코드의 논리 구조 모듈화 가능
- 프로시저가 가진 논리적 다층 구조를 프로그래밍 내부에서 표현하는 데 한계가 있음
- 불필요한 프로시저 호출 및 전역 변수 수정 가능 → 프로그램에 치명적 영향’
- 하향식(top-down) 방식

## (2) 객체지향 프로그래밍
### 객체지향 프로그래밍 (Object Oriented Programming, OOP)
- 객체라는 논리적인 개념으로 코드를 구성하는 것
- 상향식(bottom-up) 방식
- 데이터(속성)과 함수(기능)를 가진 객체 먼저 정의 → 소스코드 작성

### 객체지향 프로그래밍 필요성
- 현실 모델링
- 현실 세계의 사물이 가진 특징과 관계를 표현할 수 있어야
- **추상화(abstraction):** 현실 대상을 단순화, 일반화
- ‘has-a’ 관계 → 상호 교환 성립 X

- 논리적 계층 관계
- 복잡하고 다양한 객체 간 계층 관계 표현할 수 있어야
- ‘is-a’ 관계 → 하위 객체가 상위 객체를 대신 (일반화; generalizaton)
- **상속(inheritance)**: 상위 객체의 특성을 물려 받아 새로운 객체의 특성 추가

- 접근 제어
- 불필요한 정보 노출 & **접근 제어**할 수 있어야

### 객체지향 프로그래밍 특징
- **추상화(abstraction)**
- 현실 세계의 사물을 모델링하여 객체로 만들 때 어떤 부류에서 불필요한 요소는 배제하고 공통된 특징만 추출
- 불필요한 세부 구현은 감추고 **핵심적인 속성과 기능만 표현**
- **캡슐화(encapsulation)**
- 복잡한 내부 기능을 묶어 외부에서 불필요한 정보를 감추는 것
- 데이터(속성)와 이를 조작하는 메서드를 **하나의 객체 내부에 묶음**.
- **상속성(inheritance)**
- 부모 객체의 특성을 이어받는 것
- 기존 클래스의 속성과 메서드를 **재사용**하거나 **확장**하여 새 클래스를 정의.
- **다형성(polymorphism)**
- 상속 관계의 객체에서 같은 기능이 다르게 동작하는 특성
- 같은 이름의 메서드가 **객체의 타입에 따라 다르게 동작**.<br>
## (3) 클래스와 인스턴스
### 클래스
- 객체가 포함하는 데이터와 함수를 정의하는 문법적 요소
```c++
[클래스 정의 예시]

class MyClass {
private:
    int x;           // 멤버 변수(필드)
public:
    MyClass();       // 생성자 (선택)
    ~MyClass();      // 소멸자 (선택)
    void foo();      // 멤버 함수(메서드)
};

```

### 객체 선언
```c++
MyClass a(10);     // 스택 객체

MyClass* p = new MyClass(20); // 힙 객체
delete p; // 메모리 해제 필수
```
- 클래스 멤버를 사용할 때는 객체 이름에 멤버 접근 연산자 점 (.) 사용
